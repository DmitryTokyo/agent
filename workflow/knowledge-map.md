# Карта знаний

Где в репозитории лежит каждый вид знания, кто его меняет и как агент его находит. Свои строки репозиторий
дописывает в `docs/knowledge-map.md` и ссылается оттуда на эту карту.

## Главное правило

У факта одно место, остальные места на него ссылаются. Копий не делаем: они расходятся.

## Карта

| Что | Где | Кто меняет |
|---|---|---|
| Roadmap проекта | трекер: этапы и эпики (родительские задачи), файла нет | агент предлагает, пользователь утверждает |
| Задачи и статусы | трекер: описание (Problem, Goal, Links) и копии утверждённых версий `plan.md` комментариями | по правилам постановки задач |
| Критерии и границы задачи | `plan.md` в папке задачи (`.ai/`); в трекере — только копия, обратно не читается | агент пишет, пользователь утверждает |
| Зачем проект, для кого, ограничения | `docs/intent.md` | только пользователь |
| Точка входа агента | `AGENTS.md` — коротко, ссылки на остальное, фактов нет; `CLAUDE.md` и файлы других харнессов только ссылаются на него | агент после ОК пользователя |
| Общий порядок работы | `~/dev/agent/workflow/` | агент предлагает, пользователь утверждает |
| Предпочтения в общении | для всех репозиториев — `~/.claude/CLAUDE.md`; для одного — строка в `AGENTS.md` | агент предлагает, пользователь утверждает |
| Решения: почему так | `docs/adr/NNNN-<суть>.md` | агент предлагает, пользователь утверждает |
| Термины | `CONTEXT.md` — глоссарий | агент предлагает, пользователь утверждает |
| Правила работы агента в репозитории | `docs/agents/*`: `code-rules`, `testing`, `git`, `hygiene`, `issue-tracker`, `product`, `stack`, `domain` | агент предлагает, пользователь утверждает |
| Правила общего скилла для репозитория | `docs/agents/skills/<имя-скилла>.md`; скилл читает файл первым шагом, его правила важнее текста скилла; цепочка шагов — `CONTRIBUTING.md` «Feature workflow» | агент предлагает, пользователь утверждает |
| Eval-сценарии правил и скиллов | `evals/<суть>/`: задача, код и что обязательно или запрещено в ответе | агент предлагает, пользователь утверждает |
| Факты окружения | `docs/agents/environment.md` | агент предлагает, пользователь утверждает |
| Поправки агенту | `docs/agents/corrections.md` — открытые; закрытые — `docs/agents/corrections-archive.md` | агент пишет сразу, сам; закрывает после разбора |
| Документы этапов | `docs/*.md` | по цепочке задач-документов |
| Рабочие файлы задачи | `.ai/` вне git, папка = статус в трекере: нет папки (Backlog/Todo), `tasks/` (одна в работе), `waiting/`, `done/` (`index.md` → `summary.md`); `epics/<slug>/`; `inbox/` | только агент; `tasks/` пользователь может править |
| План эпика | `.ai/epics/<slug>/roadmap.md`; в трекере — копия в родительской задаче | агент пишет, пользователь утверждает |

## Факты окружения

Один факт — одна запись из трёх полей. Без поля «Когда важно» агент не знает, где применить факт: он либо спрашивает, либо
применяет везде.

```markdown
## <Факт коротко>
- Факт: <что верно>
- Когда важно: <в каких действиях агента это меняет результат>
- Что делать: <правило для агента>
```

## Как агент ищет знание

1. `AGENTS.md` → ссылка на нужный раздел.
2. Факт в одном месте из карты; не нашёл → спрашивает пользователя и предлагает, куда записать ответ.
3. `.ai/done/` — только по просьбе пользователя: `index.md` → `summary.md` → одна ссылка.
